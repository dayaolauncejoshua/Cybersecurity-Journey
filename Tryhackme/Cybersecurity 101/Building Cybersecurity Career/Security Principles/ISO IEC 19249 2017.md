# ISO/IEC 19249:2017

    ISO/IEC 19249:2017 describes five architectural principles and five design principles for creating secure products, systems, and applications.

### Five Architectural Principles

    1. Domain Separation - Separates components into domains with different security attributes and privileges.
    Example - The OS kernel has more privileges than ordinary applications.

    
    2. Layering - Organizes a system into layers, each with specific responsibilities and security controls.
    Example - Network security controls applied at different OSI layers


    3. Encapsulation - Hides internal implementation details and controls access through defined methods or interfaces.
    Example: An application accesses a database through an API


    4. Redundancy - Uses backup components or duplicate resources to improve availability and, in some designs, integrity
    Example: A server has a backup power supply.


    5. Virtualization - Creates virtual environments that share physical hardware while providing logical separation.
    Example: Running suspicious software in an isolated virtual machine.

### Five Design Principles

    1. Least Privilege - Give users and processes only the permissions necessary to perform their tasks. Minimum permissions, need-to-know, restricted access.
    Example: An employee who only needs to view a document receives read-only access.


    2. Attack Suface Minimisation - Reduce the number of potential entry points an attacker could expolit. 
    Disable unused services, remove unnecessary features, and reduce entry points.
    Example: Disable unnecessary services and remove unused applications from a Linux server.

    
    3. Centralized Parameter Validation - Validate user input and other parameters through a consistent, centralized mechanism. 
    Validate input, reject invalid parameters, centralized validation.
    Example: A web application checks input length, type, and permitted values using a shared validation library


    4. Centralized General Security Services - Manage shared security functions through centralized services rather than implementing them separately throughout the system.
    Centralized authentication, shared security services, and common security mechanism
    Example: Multiple applications use a central authentication service to verify users.
